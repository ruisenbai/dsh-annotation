# DSH Annotation

[English](README.en.md)

在 DeepSeek Harness Web 的助手回复中选中文字，保存与原文关联的注解，再通过官方消息输入框发送。注解记录保存在当前浏览器；已发送的记录仍可重新附加到下一条消息。

## 使用

1. 在一条助手回复中选中文字，点击 **添加注解**。重叠选区直接创建独立注解。
2. 在原文旁的输入条写下注解，按 Enter 或点击对号保存；Shift+Enter 换行。内容可以留空，空内容表示只标记原文。编辑条不重复显示原文、序号或操作说明。
3. 新注解默认随下一条消息发送。输入框左上角以圆角提示显示已附加数量，左侧边距与官方添加文件按钮一致；悬浮可查看原文和注解，取消图标只在悬浮或键盘聚焦时显示，点击提示可展开或折叠注解记录。发送文字、图片或文件时，注解走同一官方输入框。
4. 输入框模型选择按钮左侧的注解按钮可显示或隐藏记录。记录采用与官方任务栏相同的宽度、内边距、半透明材质、标题和状态图标布局；列表从标题向下展开，每行只显示注解内容；回形针控制本次附加，待发送用静态状态点表示；地图定位图标跳转原文时保持记录框原有的展开状态，草稿还可编辑或删除。空注解内容在记录中保持空白。
5. 发送后，记录框自动隐藏。需要再次发送时，打开记录并点击对应回形针；原注解 ID 和正文数字气泡不增加。输入框提示的移除按钮只取消本次附加，不删除记录。

已发送消息的正文上方显示“1 条注释”或相应数量的紧凑标签。单条注释悬浮时预览原文和注解，双击可定位原文；多条注释点击标签可展开或折叠列表，列表显示每条原文和注解，右侧地图图标用于定位。历史 Diff 注释可读，但不提供定位操作。注解记录框直接使用官方任务框的半透明背景和模糊效果；其他半透明插件浮层使用细颗粒磨砂效果。

新对话没有注解时，不显示记录框或空状态文字。正文中的气泡定位在所选文字末行末字的右上角，跟随原文滚动，滚出可见区域后消失。原文平时没有常驻背景和下划线；悬浮或点击气泡时才高亮选区。新增输入条与气泡卡宽约 392 像素，窄屏自动收缩，固定圆角，优先显示在选区末行末字下方且不遮挡原文。输入区默认一行、随实际换行自动增高，最多显示七行；超出后使用宿主风格滚动条并支持鼠标滚轮，不能手动拉伸。新增输入条的对号在单行时上下居中；气泡卡的“取消”和“保存”保持单行，正文附近空间不足时缩小文字区以保留按钮。新建输入条点击外部会抖动提示；第三次点击外部或开始在官方输入框输入时自动保存。按 Esc 可暂存未完成编辑。

代码 Diff 批注功能已移除。旧 Diff 批注及其原始快照仍可在历史消息中查看；浏览器里保存的旧 Diff 草稿和失败批次保留为只读记录，不再编辑、附加或发送。

## 设置

**设置 → 注解** 提供启用开关、保存新注解后自动附加开关和可选的插件更新操作。关闭自动附加后，可用记录行的回形针手动选择。设置修改经宿主保存后生效；关闭插件会移除注解界面和输入框附着，保留本地注解数据。插件不提供隐藏思考、工具调用或其他会话内容的设置。

## 安装与构建

本仓库现以 DSH `0.1.7-rc.1` 为精确宿主版本；插件依赖、锁文件和本地构建均已更新。宿主源码未修改。

在插件目录中使用现有依赖构建：

```bash
./node_modules/.bin/tsc -p tsconfig.build.json
./node_modules/.bin/tsdown
node scripts/verify-bundle.mjs
```

本地安装使用 DSH 的插件管理命令和构建后的本地包；安装完成后重启 Web 宿主或等待其插件热重载。具体准备过程见[开发说明](docs/development.md#install-and-verify)。

## 数据与兼容

未发送的选区、注解、暂存编辑和重试记录保存在浏览器 `localStorage` 的 `dsh-annotation:v1:<session-id>` 及待归并的 `:journal:<id>` 键中。多页面编辑先写各自的记录，再在浏览器锁内合并；锁不可用时记录仍可读取，但暂不合并。发送时固定本批注解及可选输入文字、附件身份；失败重试复用原载荷。已发送注解重新附加时继续使用原记录，不会生成第二条注解；首次与再次发送后的助手回复中，“注解 N”均可预览注解并点击定位原文。发送后的注解来源和意见进入标准用户消息与模型上下文；未发送内容只在当前浏览器中。

聊天正文的流式更新只重新解析变化的消息；注解状态未变化时，不重复写入浏览器存储。

新发送固定使用协议处理方式 `answer`。协议仍可读取历史 `rewrite`、`modify` 和 `supplementalTo` 数据，历史消息与冻结重试载荷不会被改写。旧存储版本按原有校验规则迁移。详情见[数据模型](docs/data-model.md)、[兼容性说明](docs/compatibility.md)和[隐私说明](docs/privacy.md)。

## 开发验证

```bash
./node_modules/.bin/tsc -p tsconfig.build.json --noEmit
./node_modules/.bin/oxlint --deny-warnings src tests scripts
./node_modules/.bin/vitest run
node scripts/browser-test.mjs
```

浏览器检查覆盖宽屏亮色、窄屏暗色、记录框布局、输入框提示、附加和原 ID 重发。构建产物验证使用 `node scripts/verify-bundle.mjs`。真实宿主的完整交互仍需要在目标 profile 中检查。

## 限制

- 未发送草稿不会跨浏览器同步；已发送记录可从 Session 历史恢复。
- 跨助手消息的选区不支持；单条消息内的 Markdown、代码和表格选区依赖宿主当前的正文 DOM。
- 浏览器缺少 CSS Custom Highlight API 时，仍可用数字气泡和定位原文。
- 模型只有返回有效的注解确认标记时，记录才从已发送变为已处理。
