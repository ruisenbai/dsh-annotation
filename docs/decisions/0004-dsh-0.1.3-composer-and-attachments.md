# Decision 0004: DSH 0.1.3 composer and attachments

Status: accepted

## Context

DSH `0.1.3-alpha.1` uses a Lexical contenteditable composer and one ordered image/file attachment collection. Annotation submission must preserve editor-owned text and file-reference chips, keep attachment order, and retain retry requirements after a refresh.

## Decision

The Client claim and Host command enable `attachments`. The Client forwards `SubmitAttachment[]` through the Session-addressed command Remote, and the Host appends admitted `ImageBlock` and `FileBlock` values in their received order. Attachment-free submissions may use the Session command fallback. Images retain the official viewer; files display their durable name and size.

The outbox records attachment count and ordered kinds without attachment bytes or temporary upload receipts. Retry checks that count and order before transport; a record without attachments cannot gain them on retry. Changing attachment count or kinds requires discarding the pending record and making a new submission. Legacy image-only metadata remains readable; annotation protocol v2, the storage key, `storageVersion: 2`, and stable submission-derived message ids remain unchanged. Attachment contents are not fingerprinted, so users must reselect the original attachments after a refresh.

Composer focus restoration uses the official input's DOM markers and browser Selection. It records visible offsets without the hidden annotation token, places a caret outside noneditable reference chips, and never replaces the Lexical document. A request may restore only the same connected, editable element with unchanged visible text and no intervening user focus change. When no recorded selection is available, the caret moves to the end. The empty annotation Dock keeps an invisible anchor so the last composer selection can be recorded before the first annotation.

## Consequences

- DSH owns attachment uploads, durable attachment blocks, editor text, and reference chips; the plugin owns annotation payloads and their retry metadata.
- The official composer's DOM markers, selection behavior, and command attachment types require review on each host upgrade. The plugin does not depend on Lexical internals.
- Required verification covers ordered mixed image/file admission and display, missing or mismatched retry attachments, legacy image-only recovery, and Lexical caret restoration without text replacement or focus theft. A fixture run alone does not verify installation into a real DSH Web profile.

The [compatibility checklist](../compatibility.md#upgrade-checklist) owns the complete upgrade checks. [Dependency source](../compatibility.md#dependency-source) owns source provenance and isolated verification.
